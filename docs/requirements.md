## 1. 产品目标与范围

GB28181 Hub 为符合目标标准的真实设备、下级平台、上级平台和第三方客户端提供视频接入、协议控制、媒体接收与分发、设备管理和协议操作工作台。产品必须能够单独安装、启动、升级、运维和完成第三方互操作验收。

### 1.1 硬性约束

| 编号 | 要求 |
| --- | --- |
| HUB-R-001 | 接入网关采用 Java + Netty，自研 SIP 内核并实现约定版本的 `jain-sip-api` 公共接口及行为。不得使用、包装、移植或参考 `jain-sip-ri` 实现。 |
| HUB-R-002 | 管理后端采用 Spring Boot + Spring Cloud Alibaba；管理与接入均支持横向扩展，媒体资源独立扩展。 |
| HUB-R-003 | 前端采用 Vue 3 + TypeScript，包含管理页面和协议操作页面。 |
| HUB-R-004 | 接入不依赖管理服务、管理数据库或管理缓存。接入向管理发送的状态、业务结果、配置应用结果和报文记录只能经 MQ 上报。 |
| HUB-R-005 | 下行命令与配置也统一经 MQ 交付，这是本产品选定的设计规则。管理不得通过同步 HTTP / RPC 绕过命令链路直接操作网关。 |
| HUB-R-006 | GB 互通边界只使用标准定义的 SIP、SDP、MANSCDP、MANSRTSP 和媒体协议，不依赖厂商私有消息、私有编码或指定对端的管理 API。 |
| HUB-R-007 | 自行维护账号、数据库、媒体服务、标准索引、测试与部署资产；不得导入或运行时引用其他产品的规则服务、代码模块、测试实现或配置中心。 |
| HUB-R-008 | 正常业务、协议诊断和负向测试分开标记；任何阶段不得用伪造应答、忽略必选字段或禁用认证冒充完整符合性。 |
| HUB-R-009 | 完整实现 GB/T 28181-2022 与 GB 35114-2017 的全部适用功能，包括 A / B / C 级设备接入、平台安全互联与上下级联、用户终端、安全媒体和证书 / 密钥服务对接；不得以可选插件或后续版本替代完整交付。 |

“无私有协议”约束的是第三方 GB 互通。产品内部 REST、MQ、进程间媒体协调以及浏览器播放接口可自行设计；标准定义的 `X-GB-Ver` 等头域必须正常支持。

### 1.2 范围口径

- 完整目标包括注册、实时点播、全部适用控制及配置、报警、查询、心跳、历史检索、回放、下载、校时、订阅、语音、升级、抓拍、平台互联和扩展类型。
- 以 SIP 监控域平台、SIP 客户端、媒体接收与分发节点、上级 / 下级平台为产品角色，支持普通 IPC、多通道 NVR、报警、音频、移动及扩展设备接入。
- 非 SIP 私有设备转换网关不是产品角色；4.2、6.5—6.8 的角色适用性须在能力清单中说明。GB 边界上仍可接入第三方合规转换网关。
- GB 35114 的 A / B / C 级能力均必须实现并分别验收。运行时可按设备与域选择安全配置，但“可配置启停”不等于“实现可选”；基础第 8 章也必须完成。
- 不承诺所有品牌所有固件均可互通。设备版本或能力不匹配时提供条款、协商结果和抓包诊断，不暗中加入旧版或私有兼容分支。

## 2. 使用者、对象与计数

| 使用者 | 主要任务 |
| --- | --- |
| 平台管理员 | 配置平台身份、接入策略、设备凭据、用户权限、级联关系和存储策略 |
| 业务操作员 | 目录查询、预览、回放、下载、语音、PTZ、报警处理和设备配置 |
| 协议工程师 | 生成与编辑报文、查看时序和标准原文、验证第三方行为、导出证据 |
| 运维人员 | 容量、节点、MQ 积压、媒体状态、故障恢复和审计 |

| 名词 | 定义 |
| --- | --- |
| 设备 / UA | 有独立 SIP 身份、鉴权与注册生命周期的协议代理 |
| 通道 | 设备下可独立寻址的媒体或业务对象，不等于独立注册设备 |
| 注册绑定 | UA 与某监控域、Contact / 传输连接之间的有效绑定 |
| 对话 / 事务 | SIP 的两种不同生命周期对象，不可用业务任务 ID 替代 |
| 操作 | 用户一次业务意图，可能包含多次 SIP 事务、XML 应答和异步通知 |
| 媒体源 / 媒体会话 | 一份源内容与一次传输会话分别计数；一路源可向多个观看端分发 |
| 所有权代次 | 接入域用于防止旧节点继续操作资源的单调递增版本，只在内部使用 |

DeviceID、ChannelID、平台 ID 均按字符串存储与传输。20 位设备编码按附录 E 的 8 + 2 + 3 + 1 + 6 位结构校验，不能使用 JavaScript 数值或数据库数值类型承载。

## 3. 标准符合性要求

### 3.1 通用规则

| 编号 | 要求与验收依据 |
| --- | --- |
| HUB-C-001 | 信令同时支持 UDP、TCP；TCP 长连接、分段与合并读取均正确。依据 4.3.2、9.1.1。 |
| HUB-C-002 | GB 信令按 GB 18030 编解码；`Content-Length` 按最终正文的字节数计算。内部 API 可用 UTF-8，错误字节不静默替换。依据 6.10。 |
| HUB-C-003 | 注册及相应响应按附录 I 携带 `X-GB-Ver: 3.0`。未知或不匹配版本进入诊断，不能改写成已符合 2022。 |
| HUB-C-004 | 注册缺省 86400 s，不短于 3600 s；注册失败重试通常不短于 60 s；刷新须预留处理时间。依据 9.1.1，故障场景与标准配置分别保存。 |
| HUB-C-005 | 心跳缺省 60 s，连续超时缺省 3 次；注册失效、TCP 断开与业务离线各有原因记录。依据 9.6.1。 |
| HUB-C-006 | 基础鉴权、SIP `Date` / `Note` 信令摘要、访问控制按第 8 章实现。摘要输入、算法和重放处理必须有审核后的规范依据，不能把 REGISTER Digest 等同全部安全要求。 |
| HUB-C-007 | 9.10 的 SIP 授时格式按 GB 专门规定处理；标准时间为北京时间，内部存 UTC 和明确时区。协议定时器使用单调时钟。 |
| HUB-C-008 | SDP、Subject、SSRC、RTP / RTCP、PS / PES / PSM、时间戳与媒体结束按 4.3.6、附录 B—D、G、K、L 实现；不会因为可播放而跳过协议校验。 |
| HUB-C-009 | TCP 媒体支持 RTP 封装的 PS 和 RFC 4571 定帧；支持协商主动 / 被动角色，连接失败重试间隔至少 1 s、重试至少 3 次。信令 TCP 与媒体 TCP 分别配置和测试。 |
| HUB-C-010 | 多响应正确关联 SN，默认串行、逐批确认和背压；单条记录数不超过 10000，按字节大小选择合规传输与分包。空结果 `SumNum=0` 且不携带记录列表。依据附录 M。 |
| HUB-C-011 | 每种命令分别定义语法、字段语义、前置状态、SIP 结果、业务应答、异步通知和效果证据；标准未规定的异常处理标为产品策略。 |
| HUB-C-012 | 标准特殊规定优先；其他 SIP 行为遵循引用 RFC。明确区分 GB 专用序列化与通用 JAIN API 行为，防止 GB 的特殊头域格式破坏公共接口。 |

### 3.2 不能合并的结果

| 结果层 | 含义 | 页面要求 |
| --- | --- | --- |
| 本地校验通过 | 当前规则下结构、语义与上下文合法 | 显示规则版本、检查范围与缺少的依据 |
| SIP 已确认 | 收到对应请求的成功 SIP 响应 | 不自动显示设备执行成功 |
| 业务已应答 | 收到规定的 XML / MANSRTSP 业务结果 | 校验来源及 SN / 对话 / SessionID |

### 3.4 编解码与安全的完整交付边界

附录 F.1 印刷第 119 页明确区分编码选择与解码要求。GB28181 Hub 完整的媒体接收 / 观看交付需要视频解码覆盖 SVAC、H.265、H.264、MPEG-4，音频解码覆盖 G.711、G.723.1、G.729、SVAC、AAC；G.722.1 是扩展能力，应保留清单和决定依据。档次、级别和一致性按 F.2—F.10 验收。

首个闭环可限定 H.264 + G.711，但只能作为阶段版本。转发、保存原码流和真正解码分别计状态；仅转发 SVAC 不能标记 SVAC 解码已实现。音视频输出选用标准允许的编码并明确能力；不得将并非强制全选的编码器数量伪装成标准要求。

基础安全必须有实际实现和向量验证。数字证书、TLS / IPSec、SM3、完整性和跨域身份要求逐项登记标准强度及产品支持状态。GB35114 必须完成下述全部适用能力；缺少实现、引用资料、密码产品或独立证据时，对应项标为受阻，完整交付门禁不得通过。不得将 TLS、SM4 通用文件加密或 REGISTER Digest 单独作为 GB35114 完整实现。

### 3.5 GB35114 完整安全能力

GB28181 Hub 实现安全管理平台中的中心信令控制服务器、信令安全路由网关、安全媒体服务器及所需用户终端功能，接收全部 A / B / C 级前端，支持作为上级、下级及同级平台。证书 / 视频密钥服务须按标准协议对接并交付可独立部署的配置与验收资产；合规 CA、密码产品和安全介质是明确的部署依赖，不依赖某个指定配套业务平台。

### 3.6 两标准组合与验收口径

- GB28181 业务基线为 2022；不扩展为通用 2011 / 2016 兼容项目。GB35114 中明确引用的 2016 条款仍是安全流程的依据，必须保存与 2022 的条款映射、差异和解释，不能机械删除或全部替换年份。
- 普通配置执行 GB28181 基础安全；安全配置按 GB28181 第 8.6 条执行 GB35114 专项要求。同名 Date / Note、Monitor-User-Identity、SDP 和编码字段按选定配置审核，禁止混合两套序列化规则或静默降级。
- 同一设备的不同平台绑定可有独立安全策略；域间输出是否允许解密、转码或外部分发必须显式授权。WebRTC 的 DTLS-SRTP、HTTPS 和国密码流保护分别显示，不能互相代替。
- 完整交付必须同时通过 HUB-F 与 HUB-S 全部适用叶节点以及 HUB-P 产品验收。分阶段实现只影响开发顺序；缺少安全硬件、引用规范或第三方证据不能改成“不适用”。

### 4.2 命令与事件语义

- 必须包含版本、消息 ID、命令 ID、目标域 / 设备 / 通道、接入所有者和代次、配置版本、时间、有效期、审计主体及协议关联字段。
- MQ 采用至少一次投递假设，应用实现去重、幂等、设备必要顺序和过期控制。不能承诺 MQ 与远端 SIP 设备之间的天然恰好一次执行。
- PTZ 等短时命令过期后不能补执行；停止命令也有明确生存期与顺序。重启、升级、格式化执行结果不明时须核对，不能自动换新事务重复执行。
- 请求接受、网关发送、SIP 确认、业务结果、效果验证和结果未知分别展示。
- 原始信令经 MQ 的专用追踪链路进入管理；RTP、图片、录像文件走媒体 / 文件通道，不装入 MQ 大消息。文件业务状态和索引仍通过 MQ 上报。

## 6. 媒体、文件与数据要求

### 6.1 基础约束

- 媒体接收支持 UDP 和 TCP，按协商验证流方向、SSRC、负载、地址和封装；未知媒体不能创建无主会话。
- 同源分发按附录 L 建立源标识和独立接收者关系；最后一个消费者退出才释放不再需要的源。附录 K 重建同标识链路的场景另行处理。
- 提供 WebRTC、RTSP、RTMP、HTTP-FLV、Websocket-FLV、HLS 六种输出，WebRTC 为默认低延迟浏览器路径；HLS 必须交付并标明延迟特性。GB PS/RTP 不直接交给 HTML 视频标签；网页可播放不意味着原始 GB 媒体已符合标准。

- 管理关系数据库及接入配置数据库分别支持 SQLite3、MySQL、PostgreSQL，数据库实例 / 文件和凭据始终隔离。媒体使用对象 / 文件存储；管理查询投影可由保留的事件和接入快照重建。
- 支持平台 / 域范围授权、设备操作权限、配置变更审计、敏感信息加密存放和报文脱敏；原始证据访问权限高于普通设备查看权限。

## 7. 非功能需求与容量合同

### 7.1 候选验收剖面

以下数字是 GB28181 Hub 的第一轮工程目标，需在 HUB-G-03 用真实硬件锁定，不是已达到的容量声明。10,000 UA、100 路媒体是起始剖面；扩容后的上限以测试报告为准。

| 编号 | 场景 / 指标 | 候选目标与测量边界 |
| --- | --- | --- |
| HUB-N-001 | 稳态信令 | 10,000 个独立 UA，UDP / 10,000 条 TCP 连接分别持续 24 h；心跳 60 s，协议成功率 ≥99.9%，无持续内存增长 |
| HUB-N-002 | 接入处理延迟 | 健康内网、稳态负载下，从完整请求接收至 SIP 响应写出 p95 ≤100 ms、p99 ≤250 ms，包含必要本地持久化；不含设备响应时间 |
| HUB-N-003 | 媒体吞吐 | 100 路 1080p / 25 fps / 4 Mbit/s 接收与单份转发；不转码基线与转码基线分别报告 |
| HUB-N-004 | 操作链路 | 管理接受到网关发出 p95 ≤500 ms；首帧 p95 ≤3 s；稳定播放的端到端延迟按第 5.3 条另测，不用首帧时间代替 |
| HUB-N-005 | 管理投影 | MQ 健康时接入事件到页面 p95 ≤2 s；超过 5 s 的采集新鲜度按所选事件类型显示陈旧提示 |
| HUB-N-006 | MQ 容错 | 10,000 UA 负载下断开 30 min；预算内关键事件不丢，恢复后 30 min 内排空积压；具体事件大小、磁盘与补发限速入报告 |
| HUB-N-007 | 故障与恢复 | 租约失效后阻止旧节点发送；注册恢复、媒体重建、事件恢复分别记录 RTO / RPO，不承诺已有 TCP / 对话无损迁移 |
| HUB-N-008 | 页面负载 | 10,000 设备列表分页 / 虚拟化；默认 4 个同时观看窗口单独测试，不能以观看窗口数代表后台媒体数 |
| HUB-N-009 | 管理停机 | 停止所有管理进程和管理数据库 60 min，存量接入及标准上级呼叫可持续，接入不出现管理依赖调用 |
| HUB-N-010 | 安全容量 | 普通、A、B、C 四种剖面分别测注册、验签、加解密、密钥轮换、历史回放及级联；记录密码模块与安全服务开销，普通 10,000 UA / 100 路结果不能外推为国密容量 |
| HUB-N-011 | 分发与观看容量 | 六协议扇出、1 / 4 / 9 / 16 窗、轮巡、转码、平台录像分别给出上限和资源准入结果；设备数、上游流、派生规格、输出会话与浏览器解码数分别计数 |
| HUB-N-012 | 存储剖面 | 三数据库通过同一功能与迁移验收；分别固定数据量、写并发、备份 / 恢复时长和故障行为，不宣称 SQLite 与服务器数据库具有相同集群容量 |

GB 第 5.3 条的端到端信息延迟上限为直接接入监控中心 2 s、到用户终端 4 s。完整互操作验收在记录的网络条件下按上限检查；p95 指标仅用于产品体验和容量分析，不能替代标准上限。

10,000 UA 按 60 s 心跳约产生 166.7 个请求 / s，计入 SIP 应答约 333.3 条消息 / s；首次鉴权、刷新、重传、查询和重连另计。100 × 4 Mbit/s 为 400 Mbit/s 有效载荷；分发、音频、封装和网卡双向流量另计。原始信令长期全量保存不是默认压测配置。
