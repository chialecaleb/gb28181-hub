# 架构与公共契约

以[设计](../design.md)为正本，技术栈状态见[tech-stack](../tech-stack.md)。接入域独立配置、存储、安全与恢复，不同步依赖管理数据库、缓存或认证服务；管理与接入上下行命令/事件经 MQ，禁止业务旁路 HTTP/RPC。

SIP 核心为 Java 库，不依赖 Spring、Vue 或媒体宿主。Netty 负责传输，解析、事务、对话、GB 行为与 JAIN API 适配分层。只依据公共 API/规范实现，不使用、包装、移植或参考 jain-sip-ri 及其派生实现。

每个契约写版本、身份、权限、输入输出、错误、幂等、超时、取消、顺序、副作用与资源归属。MQ 投递确认不等于设备执行；commandId、过期、重复投递、迟到结果和所有权代次要贯通，崩溃窗口用独立场景验证。管理页面显示配置意图、已应用状态与实际观测的差别。

媒体、存储、密码提供器经接口隔离。三数据库分别验证迁移和恢复；集群租约过期后旧节点必须失去副作用权限。队列、日志、缓存和会话有界，过载显式失败，不能静默丢命令再显示成功。

新增通用能力优先查证成熟开源实现，记录官方来源、日期、维护/发行、许可、兼容性、替代与退出成本；自研边界须有证据。Hub 的 SIP RI 禁令是明确约束，不被复用优先原则覆盖。接口变更同时更新消费者、文档、测试与回滚策略。
